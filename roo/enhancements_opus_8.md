## P0 — Critical

### P0.1 — Harden Firestore Security Rules
**What:** The current rules in `firestore.rules` allow privilege escalation and data spoofing.

**Why it matters:** Any authenticated user can currently:
- Read **every** user document, including other users' `fcmToken`, `email`, `activeChatId` (`users/{userId}` → `allow read: if isSignedIn()`).
- Write **any** message in a chat they belong to **with any `senderId`** — i.e. impersonate the other participant, edit their messages, or flip `isRead`/`isDelivered` arbitrarily (`chats/{chatId}/messages` → `allow read, write`).
- In groups, any member can overwrite the whole group doc — remove other members, seize admin, rename — the rule comment even admits this (`groups/{groupId}` → `allow write: if ... in resource.data.members`).
- Read **all** block records (`blocks/{blockId}` → `allow read: if isSignedIn()`).

**Where:** `firestore.rules:17-56`

**How to fix:**
- Split `read`/`create`/`update`/`delete` instead of blanket `write`.
- On message `create`, validate `request.resource.data.senderId == request.auth.uid` and that `createdAt`/`senderId` are immutable on `update`.
- Restrict `users` read to only the fields needed, or gate sensitive fields; never expose `fcmToken` to clients (only the Edge Function needs it — it can use the Admin SDK).
- For groups, separate "post a message" (any member) from "modify group metadata" (admin only): check an `admins` array.
- Restrict `blocks` reads to `resource.data.blockerId == request.auth.uid`.

```
// Example: messages create/update split
match /chats/{chatId}/messages/{messageId} {
  allow read: if isMember(chatId);
  allow create: if isMember(chatId)
                && request.resource.data.senderId == request.auth.uid;
  allow update: if isMember(chatId)
                && request.resource.data.senderId == resource.data.senderId
                && request.resource.data.createdAt == resource.data.createdAt;
  allow delete: if isMember(chatId)
                && resource.data.senderId == request.auth.uid;
}
function isMember(chatId) {
  return isSignedIn() &&
    request.auth.uid in get(/databases/$(database)/documents/chats/$(chatId)).data.users;
}
```

### P0.2 — Audit the service-account JSON shipped in app assets
**What:** `pubspec.yaml:138` bundles `assets/store-app-c9001-fa3b97881677.json` into the app.

**Why it matters:** Files named like `<project>-<hash>.json` are typically **Google service-account credentials** (private keys). Anything in `assets/` is trivially extractable from the installed APK/IPA. If this is a service account, it is a full server-side credential leak that lets an attacker send notifications, read/write your backend, etc.

**Where:** `pubspec.yaml:138`

**How to fix:**
1. Open the file and confirm its contents. If it contains `"private_key"` / `"type": "service_account"`, **remove it from assets immediately**, rotate the key in Google Cloud Console, and move all usage server-side (your Supabase Edge Function already exists for this — see `chat_notification_service.dart`).
2. If it is only a public client config, rename and document it. Either way it should not ride along unless an on-device API genuinely needs it.

## P1 — High

### P1.1 — Fix the broken message pagination
**What:** `MessagesCubit.loadMessages` mixes a "latest 30" stream with a separate paginated history and never merges them — the code comments admit it: *"This is complex. For now, let's just use the stream for the latest 30."*

**Why it matters:** Scrolling up to load older messages (`loadMoreMessages`) appends to `_messages`, but the live stream then **overwrites** `_messages` with only the latest 30 on the next emission — older messages vanish, and new arrivals can duplicate or reorder. This is a core chat UX bug.

**Where:** `lib/features/single_chat/presentation/bloc/messages_cubit/messages_cubit.dart:37-67` and `:69-99`

**How to fix:** Adopt one consistent model:
- Keep a single `List<MessageModel>` keyed by `id` (use a `Map`/`LinkedHashMap` or de-dup on merge).
- The live stream updates/ą inserts only the newest window; pagination prepends older pages.
- Merge by id, then sort by `createdAt` once, before emitting.
```dart
void _merge(List<MessageModel> incoming) {
  final byId = {for (final m in _messages) m.id: m};
  for (final m in incoming) byId[m.id] = m;
  _messages = byId.values.toList()
    ..sort((a, b) => b.createdAt.compareTo(a.createdAt));
}
```

### P1.2 — Chunk `markMessagesAsRead` batches (500-op limit)
**What:** `markMessagesAsRead` loads all unread messages and commits them in a single `WriteBatch`.

**Why it matters:** Firestore batches are capped at **500 writes**. A user returning to a busy chat with >500 unread messages will throw and silently fail to mark anything read.

**Where:** `messages_remote_data_source.dart:638-654`

**How to fix:** Split into chunks of ≤450 and commit sequentially.
```dart
const chunk = 450;
for (var i = 0; i < docs.length; i += chunk) {
  final batch = FirebaseFirestore.instance.batch();
  for (final doc in docs.skip(i).take(chunk)) {
    batch.update(doc.reference, {'isRead': true});
  }
  await batch.commit();
}
```

### P1.3 — Add optimistic send + delivery state
**What:** Messages only appear after the Firestore round-trip completes; there's no "sending / sent / delivered / read" indicator even though `MessageModel` already has `isDelivered` and `isRead`.

**Why it matters:** On slow networks the UI feels laggy and users double-send. `isDelivered` appears to never be set to `true` anywhere in the data source, so delivery ticks can't work.

**Where:** `message_model.dart:48-49` (fields exist), `messages_remote_data_source.dart` (never sets `isDelivered`), send flow in `send_message_cubit.dart`

**How to fix:**
- Emit the message locally with a `pending` status before the network call; reconcile on success/failure.
- Set `isDelivered = true` when the recipient's client first receives the message (or via the Edge Function on push receipt).
- Render single/double/blue ticks from these flags.

### P1.4 — Enable Firestore offline persistence explicitly
**What:** No explicit `Settings(persistenceEnabled: true)` / cache size configured.

**Why it matters:** A chat app must work offline (queue sends, read cached history). Defaults differ by platform; being explicit guarantees consistent offline behavior and unbounded-cache control.

**Where:** `main.dart` (after `Firebase.initializeApp`), `firestore_service.dart`

**How to fix:**
```dart
FirebaseFirestore.instance.settings = const Settings(
  persistenceEnabled: true,
  cacheSizeBytes: Settings.CACHE_SIZE_UNLIMITED,
);
```

### P1.5 — Replace generic catch-all errors with an ErrorMapper
**What:** Most data sources/repos throw or return `"Something went wrong"` / `"Can't upload image $e"`. The project's own architecture rules (CLAUDE.md) require an `ErrorMapper` producing stable error keys that the UI translates.

**Why it matters:** Users get untranslated, non-actionable English strings; the `$e` interpolation can leak internal details into the UI (e.g. `upload_image_repo.dart:18`). No localization of errors despite a full i18n setup.

**Where:** `upload_image_repo.dart:17-19`, `auth_service_fierbase.dart` (English literals), `chat_notification_service.dart` (debugPrint-only failures).

**How to fix:** Centralize a single `ErrorMapper` that converts exceptions → stable keys (`error_network`, `error_upload_failed`, …); cubits emit the key; UI calls `context.translate(key)` + `showToast`. Add the keys to `ar.json`/`en.json` + `LangKeys`.

## P2 — Medium

### P2.1 — Stop bypassing `DataBaseService` in the messages data source
**What:** `MessagesRemoteDataSourceImpl` is injected with a `DataBaseService` abstraction but repeatedly reaches for `FirebaseFirestore.instance` directly (id generation, pagination, read-marking, last-message recompute).

**Why it matters:** Breaks the persistence abstraction the rest of the app relies on, makes the data source impossible to unit-test with a fake DB, and splits Firestore logic across two access styles.

**Where:** `messages_remote_data_source.dart:146, 169, 236, 305, 373, 434, 495, 575, 643, 662`

**How to fix:** Extend `DataBaseService` with the few primitives you need (new-doc id, paginated query, batch update) and route everything through `sl<DataBaseService>()`.

### P2.2 — Move side-effects out of the data source
**What:** `MessagesRemoteDataSourceImpl` calls `ChatNotificationService.instance.sendMessageNotification(...)` and `getCurrentUser()` directly inside every send method.

**Why it matters:** A persistence data source now owns notification policy and reads global session state — two extra responsibilities that violate the layering in CLAUDE.md (data sources "must not depend on presentation"/cross-cutting services) and make sends untestable in isolation.

**Where:** `messages_remote_data_source.dart:208, 275, 344, 412, 473, 534` (notifications) and the `getCurrentUser()` calls beside them.

**How to fix:** Have the repo/cubit orchestrate "persist message → trigger notification," or fire notifications server-side from the Edge Function on new-message writes (also fixes reliability when the sender backgrounds the app mid-send).

### P2.3 — Parallelize cold-start initialization
**What:** `main()` awaits a long serial chain: env → Firebase → Supabase → CallKit → SharedPref → injector → Hive → DND → Wallpaper, all before `runApp`.

**Why it matters:** First frame is delayed by the sum of all these. Several are independent and could run concurrently; some (Wallpaper, DND) don't need to block the first frame at all.

**Where:** `main.dart:25-97`

**How to fix:** Group independent inits with `Future.wait([...])`; defer non-critical services (Wallpaper, DND, presence) to just after `runApp`. Example:
```dart
await Future.wait([
  CallKitService.instance.init(),
  SharedPref().instantiatePreferences(),
  HiveDatabase().setup(),
]);
// after runApp:
DndService().init();
WallpaperService().init();
```

### P2.4 — Generate thumbnails for 1:1 chat images
**What:** Group image upload generates a thumbnail (`uploadMessageImage`), but the single-chat path (`uploadChatImage`) uploads only the compressed full image.

**Why it matters:** Chat message lists load full-resolution images, increasing bandwidth, memory, and scroll jank.

**Where:** `supabase_storage_service.dart:211-232` (`uploadChatImage`, no thumb) vs `:95-135` (`uploadMessageImage`, has thumb)

**How to fix:** Mirror the group flow — generate + upload a `thumb_` variant, store `thumbnailUrl` on the message, and load thumbnails in the list with the full image on tap.

### P2.5 — Use relative imports inside `lib/`
**What:** Pervasive `package:chat_material3/...` imports inside `lib/`.

**Why it matters:** CLAUDE.md explicitly forbids this ("Imports: Relative inside `lib/`. Never `package:project_name/...`"). Absolute self-imports slow refactors/renames and are inconsistent with the stated convention.

**Where:** `injection_container.dart` (≈50 such imports), `messages_remote_data_source.dart:3-8`, `chat_notification_service.dart:7`, and broadly across `lib/`.

**How to fix:** Convert intra-`lib` imports to relative paths (a one-time codemod). Keep `package:` only for third-party deps.

### P2.6 — Localize denormalized "last message" labels
**What:** Last-message previews are written in hardcoded English: `'Image'`, `'Voice message'`, `'GIF'`, `'Sticker'`, `'File'`.

**Why it matters:** Arabic is the primary language (per CLAUDE.md). These strings surface directly in the chat list, untranslated.

**Where:** `messages_remote_data_source.dart:270, 339, 407, 469, 529, 593-607`; also `chat_notification_service.dart:63-68`

**How to fix:** Store a stable `lastMessageType` (already done) and render the localized label on the client from `LangKeys`, instead of persisting an English string.

### P2.7 — Add a test suite (currently effectively zero)
**What:** The only test file (`test/widget_test.dart`) is fully commented out; no unit tests for cubits, repos, or data sources. `patrol` is a dependency but unused.

**Why it matters:** Critical flows (pagination merge, read-marking, auth error mapping, optimistic send) are exactly the kind of logic that regresses silently.

**Where:** `test/widget_test.dart`, `pubspec.yaml:114` (`patrol`)

**How to fix:** Start with pure-logic unit tests for cubits using `bloc_test` + fakes for repos. Prioritize `MessagesCubit` (after P1.1), `AuthCubit`, and the storage path-cleaning helpers. Wire `patrol` for a smoke E2E of login → send message.

### P2.8 — Split and clean the DI container
**What:** `injection_container.dart` is one 300+ line file with large commented-out blocks (`_initHome`, `_initSearch`, `_initFavorites`, dead auth wiring).

**Why it matters:** Hard to navigate; dead code rots. Also `AlgoliaSearchService` (just fixed) isn't registered anywhere, so search isn't wired up.

**Where:** `injection_container.dart:76-82, 222-231`

**How to fix:** Split per-feature registration into `*_injection.dart` files (or `get_it` modules), delete dead blocks, and register `AlgoliaSearchService` if message search is intended (see P3.4).
